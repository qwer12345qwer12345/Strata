# 旧 V2/V3 存档能力迁移到 0.1.65

用户已明确选择把旧方案作为一个完整大补丁直接使用。现已实现 `legacy-session-archive`，将实际部署的控制器、V2/V3 文件核心、内存停放、缓存协议及正常退出等待合为一个补丁，适配新版 Snapshot 接口。包位置与验收见 [legacy-session-archive](../features/legacy-session-archive/README.md)。

此前提出的分层拆补丁方案由这个选择取代。Live Memory、实验性 Runtime KV Storage 与旧 Shutdown Persistent Cache 包保留作参考，从默认活动栈移除；新版仅由完整存档包负责自动持久化，避免双重写入。
## 选择依据

旧部署已有真实会话轮换与跨重启前缀恢复验证。此前 6623-token 提示在重启后恢复了 6616 token，磁盘前缀恢复约 181.7 ms，整次请求约 0.77 秒。低内存停放也已有实现，256K 上下文、32 GB RAM 下的极限峰值和拒绝条件仍需单独验证。V3 使用不可变 base/delta 段与原子替换 manifest，具备继续复用的价值。V2 与 V3 的发布机制不同，迁移时以 V3 为主要写入路径，V2 的兼容读取单独验收。

新版官方临时 SSD spill、会话匹配、Snapshot 捕获与恢复、模型/配置 identity 已承担状态管理。已退役为参考的 Runtime KV Storage 的两个补丁提供 Delta 文件核心和 Snapshot provenance，实际 ConversationSpill 生命周期接线仍未完成。其设计规定完整读取 Base 并依次应用 Delta 后恢复。这条路径在 32 GB 内存下的峰值和按前缀恢复效率尚需验证。

截至核查，PR5500 仍未合并，当前 head 为 `16b1fb71d6d97226165f35322e698701d2190e10`，父提交为旧的 `c77572806996349b49995e4f98d41b5294d36a21`，保持 0.2.15 的旧目录结构。旧包需要适配新版 API 与捕获边界，完整补丁直接应用不能代表正确迁移。[PR5500](https://github.com/Niko1221/Strata/pull/5500)

## 大补丁内部覆盖的职责

1. **存储层。** 迁入 V3 的不可变段、增量尾段、独立 checkpoint、manifest 提交和有界整理。保留旧读取器作为兼容依据，数据布局由新版官方 metadata 描述。
2. **捕获与恢复适配。** 用官方 Snapshot 的真实尺寸和 unchanged/dirty 边界决定哪些字节可以复用，迁入按匹配前缀读取。接入文件后备或有界分段捕获，使长会话无需先在匿名 RAM 中形成一份完整快照。
3. **运行时接线。** 在官方会话匹配、停放、取回、淘汰和预算管理中使用存档后端。恢复期间持有存档引用，仍被引用的段在恢复或新代提交结束后才能回收。失败后按原有缓存未命中语义重新预填充。
4. **正常退出与重启索引。** 保存当前活动会话以及需要保留的停放会话，等待已受理写入完成，再结束服务。下次启动先读索引，命中后按需读取。退出需要额外快照时仍使用有界捕获路径。

存档层与官方会话缓存之间保留一套明确的数据边界。已有 Runtime Delta 与 Shutdown 包需要依据最终接口进行整合，避免同时维护两个可写的存档所有者。

## 必须保留的旧能力

| 能力 | 新基线的验收 |
| --- | --- |
| 追加短对话只保存变化部分 | 记录新增 token、实际写入量、总磁盘占用和整理次数 |
| 恢复较短 checkpoint 前缀 | 记录所需前缀与实际读取量，并核对恢复后状态 |
| 32 GB 系统 RAM | 测量整个捕获、写入、恢复阶段的峰值 RAM、swap 和专家文件读取 |
| 多会话轮换 | 相同输入、上下文、预算下记录恢复命中和剩余预填充量 |
| 正常停止后恢复 | 单会话未切换就停止、多会话停放及在途写入分别测试 |
| 发布失败 | 在段写入、manifest 提交、整理的故障点验证已提交代仍可恢复 |
| 新旧模型状态一致性 | 由官方身份与 Snapshot 校验决定兼容性，再做逐字节状态与固定输入输出检查 |

旧版本的高命中和低预填充耗时作为同机对照基线。新接口带来的维护收益和旧方案的实际性能都纳入验收，实际通过范围记录在功能包 validation；无头长上下文峰值仍作为明确的后续验收。

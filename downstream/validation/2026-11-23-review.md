# 0.2.19 补丁和无头测试核查

核查基线为 `downstream/main` 的 `deb38a8f859009f411dc4f74318fdafe6c80b045`，固定上游为 `c6f6427d9de9016fd92d13e29740f65625261df7`。源码为 Strata 0.2.19 / Engine 0.1.65。本次修改在独立审查分支，验证使用隔离工作区。

## 已完成的旧基线测试

11 月 17 日的四轮顺序为成对行、单行、单行、成对行，使用 0.1.60、DFlash2、prior 0.5。三个正式用例均达到输出上限，所有正式用例的解码专家文件读取为零。表中是两次运行的中位数。

| 负载 | 单行 token/s | 成对行 token/s | 单行内容间隔 p95 ms | 成对行内容间隔 p95 ms |
| --- | ---: | ---: | ---: | ---: |
| Python 3072 输出 | 107.70 | 110.95 | 46.419 | 45.901 |
| 28750 输入后输出1536 | 91.20 | 89.25 | 47.962 | 46.282 |
| Rust 3072 输出 | 108.20 | 108.80 | 45.014 | 45.224 |

内容间隔是本机收到的 SSE 内容事件间隔。一个事件可包含多个 token。长输出的响应校验值有差异，草稿接受数量也有差异，因此整体速度仍含工作量变化。该数据支持暂用成对行，进一步比较需要保留输入、输出长度、接受率、分阶段时延和热状态。

Gyro-M 32K 已加载 3892 个 GPU 专家槽及 25.15 GiB 锁页 RAM 专家补集，随后可用 RAM 降到约 1014 MiB，触发实验的 1024 MiB 停止线。此次到达了专家补集加载完成阶段，正式请求和稳定解码尚未通过。降低这一停止线本身不能证明运行余量充足。

11 月 17 日之后五次正式开机基准均通过，代码用例为 91.2、93.9、98.2、93.7、95.2 token/s。实际启动仍选用旧的 0.1.60 可执行文件。[去隐私的四轮结构化结果](headless-0160-streaming.json)

## 已修复的维护和测试问题

1. `downstream/downstream` 多嵌套一层，导致脚本从子目录运行，Git 跳过引擎补丁。实际指纹变成未修改的上游树。恢复到仓库根目录的 `downstream` 后，12 项补丁的校验正常。
2. TQ CPU 补丁重复定义上游已有的 `tq_cpu_parity`，CMake 配置失败。改用上游无需 ggml 的 `tqp_cpu_test`，包含原有 TQ 类型及 1–8 token 分组的逐位数值验证。
3. QSA 补丁重复定义 `qsa_prompt_attn_parity`。复用上游目标，仅增加 K8V4 对照测试。
4. Ampere 补丁的 CTest 注册位于失效的旧条件中，测试清单匹配不到实际测试。改用现有 `tq_pascal_bench` 的关闭与开启两次测试。
5. Shutdown 和 Delta CUDA 往返目标把 `tests/core` 中的源文件误写成 `src/core`。修正了构建路径。
6. VMM overlay 使用已不存在的 `ExpertCache::kNotResident`，修正为当前 API 的命名空间常量。
7. 测试脚本原先直接反向应用工作区补丁，Settings 重生成后反向应用会中途失败，且此前已移除的补丁未恢复。改用临时 Git index 做存在性校验，工作区源码不参与反向修改。CTest 使用 `--no-tests=error`。
8. Live Memory 的两项 Python 测试在功能分支中存在，但未纳入新的功能包。补齐测试 overlay 和执行入口。
9. 对由功能包明确声明为 opt-in 的新环境项，Settings 生成步骤补全其状态。上游自身仍有 41 个空状态项，完整 Settings 状态测试保留此失败。

测试硬件为 RTX 3080 12 GiB / SM86、Core Ultra 7 270K Plus、32 GB DDR5。CachyOS kernel 7.3.3、NVIDIA 620.70.06、NVCC 13.4.92、GCC 16.2.1。编译结束后执行 GPU 测试。

- 完整功能栈的 `strata` 编译通过，报告版本 0.1.65。
- 11 项选定 CTest 全部通过，包含 TQ CPU 基线/VNNI、TQ GPU 基线/成对行、K8V4 IMMA、RAM 块、容量策略、CUDA VMM、Delta Host/CUDA 往返和关机存档 Host 测试。
- 另行运行关闭/开启成对行，两边 30 条 `SUM` 校验值完全相同，各自报告零失败。

## 已确认的运行时边界

Runtime KV Storage 的两个补丁提供 Delta 文件核心和 Snapshot 边界适配。真实 ConversationSpill 轮换尚未调用这些 API，因此当前没有运行时减少重复写盘的实测收益。

Shutdown Persistent Cache 在退出循环时保存 RAM cache 已停放的条目。它没有在退出前捕获仍活动的当前会话。仅完成一次会话后退出时，RAM cache 可以为空。这一行为需要真实服务退出验收，现有 Host 测试覆盖文件与索引。

Live Memory 的 `MEMORY` 命令仍拒绝 `src.complement_ready()` 的低内存模式。补丁中的视觉接线位于 `serve/images.py` 的生图模块，`chat/completions` 识图仍由 `Service._vision_up()` 调用上游 VRAM 命令。当前 GPU 专家补集模式会被该命令拒绝。新的识图结构见[显存临时借还方案](../design/GYRO_VISION_VRAM_LEASE.md)。

## 上游版本对本机的意义

| 版本 | 核查结果和本机价值 |
| --- | --- |
| 0.2.16 / 0.1.62 | 引擎使用自己的数值实现，目录改为 engine/app/terminal。需重新适配测试与构建路径。Linux 加载前释放旧文件缓存有助于启动内存压力，服务绕过 launch 时需核实是否经过该路径。 |
| 0.2.17 / 0.1.63 | route tail skip 默认关闭，符合保留质量的目标。CPU pool 的依赖调度让同一专家完成 gate/up 后即可做 down，减少全局等待。Unsloth 的 RAM 预算改变有特定模型适用范围。 |
| 0.2.18 / 0.1.64 | 新增 Hy4 独立引擎。其 AVX-VNNI 冷专家和受限分块搬运思路可参考，Hy4 本身的容量要求从 64 GiB RAM 起。 |
| 0.2.19 / 0.1.65 | SM86 默认栈、dense 搬运及量化融合、PLE 压缩/复制流、预填充 CPU 侧流水、DFlash2 attention Tensor Core 默认路径均值得进入新基线。DFlash2 INT8 GEMM 仍为 `STRATA_DF2_GEMM_TC=1` 的可选对照。Gyro 专家使用 TQ 路径，K-quant 专用优化的收益需按格式判断。 |

0.2.19 发布说明中的 Ampere 速度提升使用 IQ3_S、IQ2_XS、UD-Q4_K_XL 等模型，不能据此计算 Gyro-S 在本机的预期提升。Inkling 的 SQ-10 和 DSpark 属于另一条模型/引擎路径，DSpark 的实现思路可供研究，其实际收益需要专门移植和验证。

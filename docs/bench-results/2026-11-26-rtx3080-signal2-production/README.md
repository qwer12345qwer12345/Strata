# Signal 2 production on RTX 3080

The engine follows [Strata 0.2.22, Qwen engine 0.1.69](https://github.com/Niko1221/Strata/releases/tag/v0.2.22) at `b28ca95e`. The build targets CUDA SM86 with a 16-row verification limit. Both NoPLE models use the existing external BF16 PLE table and independent expert profiles, parked sessions, spill folders and V2/V3 disk archives. The first validation boot uses [Signal 2 Gyro-S NoPLE](https://huggingface.co/agentionai/Signal-2-Flash-Next-Gyro-GGUF). [Huihui Gyro-S NoPLE](https://huggingface.co/agentionai/Qwen3.8-Flash-Next-Gyro-abliterated-Huihui-GGUF) has a second GRUB entry for direct serving.

## Changes selected for production

| Setting or patch | Why it stays |
| --- | --- |
| INT8 fused TQ prefill | With fusion off, 29K-token time to first content rose from about 11.4 to 16.4 seconds. A separate dequantization pass took 2.80 seconds and the less efficient down projection added 1.66 seconds. |
| K8V4 IMMA prompt attention | This uses the INT8 Tensor Cores for QK while keeping four-bit V. Disabling it raised the QSA part of the 29K prompt from 1,865 to 2,041 ms and first content from 11.37 to 11.64 seconds. The separate K8V4 decode-TC change is retired. |
| SM86 DFlash2 shape table, DP4A | Specializing the tile to the actual draft width cuts multiplications for idle columns and improves activation reuse. The fixed-input 8-column gate/up went from 41.04 to 32.53 µs, down from 28.96 to 19.59 µs and output from 14.54 to 11.58 µs. The one-column FC went from 45.49 to 23.04 µs. Real-draft pack parity passed in the original kernel evaluation. The new port carries the DFlash2 table only. |
| Resident Fetch 2 and 25% expert profile pin | Fetch admits experts on PCIe copies already being made. Removing fetch in earlier matched runs lost about three points of VRAM hits. Removing the pin raised hits from 53.0% to 62.7% but increased the neural three-row p95 from 33.7 to 56.9 ms. |
| GDN TC and Q8 hyper-connections | Disabling GDN TC added 290 ms to 29K cold first content. The Q8-off run increased cold three-row p95 from 33.4 to 34.5 ms and lost two points of VRAM hit rate. Both new GGUFs use Q8_0 hyper-connection up matrices. The upstream shared-memory load correction applies to this path. |
| Warm cuBLAS, 192 MiB VRAM reserve | 0.1.66 began waiting for cuBLAS warm-up before sizing the expert cache. At the same 448 MiB reserve, desktop startup with the old Gyro-S changed from 5,934 slots with 0.1.65 to 5,708 with 0.1.69. Disabling warm-up recovered 222 slots. Keeping warm-up and setting the reserve to 192 MiB reached 5,964 slots and 363 MiB free at readiness with a completed short request. The resident KV setting was held constant. |
| Session archives, ChatML boundaries, repetition retry and vision lease | These preserve service behavior independent of speed. The archive port also preserves explicitly pinned snapshots when a newer snapshot extends their prefix. The vision helper returns its borrowed expert VRAM when image encoding finishes. |

## Earlier tests retired

The failed or slower cases are closed. Decode TC (fork PR6) raised matched verify-window latency. F16 fused TQ (PR7) added 380 ms to gate/up. Q8 persistent reads (PR9) regressed prior production. Tail skip 7 repeatedly triggered cancellation on repeated content. The CPU-prefill-share variants raised short first-content time, and the 4K prompt chunk and upstream-only elastic vision hit the memory guard. All stay out of production.

Paired expert rows, CPU AVX-VNNI, the extra Dense dispatch table, the local BF16 compact upload and independent copy, GDN tile and fusion variants, and the standalone NOWAIT A/B showed no meaningful gain in this data. The custom experiments are frozen and their old arms are out of the boot run. Spec 3 lowered p99 but reduced throughput on the long code workload; spec 4 stays. Lookup width 16 stays available for matching suffixes through the upstream implementation. Its value depends on the generated content, so suffix windows and neural draft windows are reported separately.

## Upstream selection and next Signal 2 boot

The production build keeps the [Q8 shared-memory read correction](https://github.com/Niko1221/Strata/commit/f5da789691228f86a89621810e11694ce13b3d92) and the [fused prompt normalization correctness fix](https://github.com/Niko1221/Strata/commit/ed5bff88). [The upstream allocation report](https://github.com/Niko1221/Strata/commit/6e45f7fb) corroborates the earlier cuBLAS timing change. Its Windows paging margin changes are platform-specific. The SM86 single-row Q8 projection and mid-coverage CUDA adaptation defaults apply here. The first Signal 2 headless run attempts one production baseline, one arm with the Q8 single-row kernel disabled and one with the coverage-based adaptation disabled. Around 6,000 of 24,576 expert slots puts this host in the 15–65% range where the upstream adaptive policy raises the admission cadence and keeps a longer activity history. Compare first-content time, p95/p99 by width and source, expert hits and disk reads. The production baseline also checks a cold and cached image.

The SM86 down-workspace experiment accepts IQ4_NL/Q2_0 expert down matrices. These Gyro files use Hadamard-folded TQ experts. The tiny-cache policy stays off after upstream documented a regression on a 3080 Ti. K/V stay K8V4; the upstream split-attention optimization is for INT8 K and INT8 V. The 12 GB CUDA prompt ceiling remains 8K to limit the slots lent to prefill. The upstream application-level cache budget and multi-GPU reserve options are outside this single-card server configuration.

Verification before real-model switching: eight native CTests, including four Q8 Tensor Core cases and K8V4 IMMA prompt parity. The downstream patch is [available as plain source](../2026-11-25-rtx3080-patch-review/strata-0.2.22-gyro.patch). The [previous run and desktop capacity probe](../2026-11-25-rtx3080-patch-review/README.md) include the comparison details.
